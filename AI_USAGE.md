# AI usage

## What it produced

All of the code, tests, migrations, Docker files and documentation in this repository were generated by these
agents and the orchestrating session; no line was typed by a person. How the work was directed:

- **The design was written first, by the orchestrator, before any code**: semantics of time and rule periods,
  the schema with constraint names, the supersede algorithm, the 30-day window and its invariant, the lock
  hierarchy, the error contract, the attempt log, the test strategy (including the shape of the concurrency
  demonstration). The agents implemented against that contract. The resulting choices are in `DECISIONS.md`.
- The orchestrator also made the tooling and integration changes: `backend/ruff.toml`, universal lockfiles,
  the frontend Vitest configuration, the live acceptance run and the documentation.

## Where output was corrected, rejected or deviated from the design

Real events, from the agents' reports and the history:

- **Accepted deviations from my design:** Angular 21 instead of 22 (the installed Node 24.11 is below the 22 CLI's
  minimum); the SPA reuses an idempotency key after any failure that gave no definitive answer, including a 5xx
  with a body (my design said "no response" only; a retry after an ambiguous 500 must not create a second
  dispense); the cursor trail is a repeated query parameter, not one delimited value; the cursor JSON has a
  version field; the engine does not pre-filter its history because the date arithmetic already ignores
  out-of-reach rows; seed counts are generated rows plus four demo medicines and `PT-DEMO` (504 / 6,010 / 2,501).
- **Instructions an agent declined, correctly:** the perf agent did not add the `--seed-from-api` flag I asked
  for, because the benchmark always discovers its parameters through the API and the flag would have been dead.
- **Defects the agents found in their own or each other's work:** replaying a rejection was equal as JSON but not
  byte-identical because PostgreSQL's `jsonb` reorders object keys (context keys are now sorted on first answer and
  on replay); `datetime.fromisoformat` accepts a trailing NUL, so a forged dispense cursor could pass (cursors are
  now checked by an exact round trip); a differential-test generator was biased towards 0/1/29/30-day gaps and let a
  UTC-instead-of-SAST mutation survive (fixed until it was caught); a connection with no timeout could hang
  migrations and tests (now bounded); the SPA showed a pointless "no endpoint matches" page for an unroutable
  medicine code, and a backend message embedded raw UTC instants that the SPA showed as dates a day off the SAST
  business date (both found by driving the SPA against the real API; fixed with regression tests); a redundant
  type check in the cursor codec was removed after mutation testing showed it was dead.
- **Environment problems that changed the plan:** the API-core agent was stopped by a plan session limit after
  committing its work but before reporting, so I re-verified its tests and wrote the hand-off to the next agent
  myself; Docker pulls ran at 4 to 9 KB/s, so the infrastructure agent loaded the three base images from a
  registry mirror and verified every manifest and layer against the digests read from Docker Hub (the
  Dockerfiles use the official tags); lockfiles compiled on Windows lacked `uvloop` for the Linux image (recompiled
  universal); the clean-clone check showed the frontend tests failing in a container that reports eight CPUs
  (4 to 30 of 288 timed out, all pass on the host), fixed by capping the Vitest workers.
- **My own drafts of the documentation were fact-checked against the code and measurements** and several
  imprecise statements were corrected before committing (index counts, the repeat counts of the flake loop, the
  wording about lock hold times).

## How it was checked

- **Backend:** 1,386 tests pass in the container from a fresh clone (unit 278, db 163, api 662, concurrency 41,
  seed 120, perf 116, locking 6): `docker compose run --rm api pytest`. **Frontend:** 288 tests.
- **Mutation checks** (a deliberate bug applied, the suite must fail, then reverted): about 100 mutants of the
  domain engine (every behaviour-changing one killed); 12 of the concurrency design (no pair lock, history read before
  the lock, no medicine lock, no key lock, REPEATABLE READ snapshot, window from `now()`, insert-then-delete and
  more), each failing at least one test; about 17 of the dispense service and listing; about 10 of the migrations
  and constraints; 20 deliberate data corruptions against the seed's self-check; 14 of the SPA; 4 of the query-plan
  tests. The concurrency suite was repeated 25 times on each of three trees: 0 flakes.
- **Live acceptance run** of 35 cases against the running stack (rule boundaries around SAST midnight, backdating,
  every violation, the attempt log, the exclusion constraint through raw SQL, 12 simultaneous requests, replays).
- **Browser run** of the SPA against the real API, in Chrome with the browser zone set to America/Los_Angeles, on the
  dev server and behind the project's nginx configuration.
- **Clean clone:** `docker compose build --no-cache`, `up --wait`, seed, the container test suite and the
  benchmark all ran from a fresh `git clone` of the repository.

## Limits

Chrome was the only browser tried. The nginx container's DNS-based upstream was exercised through compose, not
in a long-running deployment. No type checker was run on the Python code, and no automated accessibility audit on
the frontend. Review of the code by a person is not part of this record: the author of the submission is expected
to read and be able to explain it.
